How it works

This page runs only the planning engine. In the full project, the engine sits behind a Django REST API: a GET request returns a plan right away, while a POST queues a background job that a Celery worker picks up from Redis, runs on the Go engine, and stores in MySQL before exporting the result to S3.

Filled boxes are what this page runs. Everything else needs a server; run it locally with ./run.sh web.

Backend details

  • Each job is keyed on a SHA-256 hash of its full input, stored as a unique key in MySQL. A repeated request gets the existing job back instead of a second computation, even when two arrive at once.
  • Workers claim a job with a single conditional update, so a job Redis delivers twice still runs once.
  • If Redis is down, the API answers 503 and leaves no orphaned job behind.
  • Finished plans are exported to S3-compatible storage and returned with a presigned download link.

How it's tested

  • The Go engine is a port of the Python original and must return byte-identical JSON: 37,699 test cases compared, 0 differences.
  • A separate brute-force solver checked the engine's feasible and infeasible answers on 99,069 random course catalogs, with no disagreements.
  • Every plan is re-checked by an independent verifier before it's shown, on this page too.
